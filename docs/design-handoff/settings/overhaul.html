Atoms settings, on the v2 tokens

Rebuilt against docs/design-handoff/tokens/README.md. That document already diagnosed this exact failure a month ago: “the v1 system read as generic AI-designed iOS-dark.” Its answer was flat cards, no accent-tinted fills, no accent borders, and colour that states a category rather than decorating one. The previous mock broke four of those rules at once.

What was violating the tokens

Accent-tinted status card. An amber fill with an amber border behind “One thing to choose.”
Rule: flat cards, no accent-tinted card fills, no accent borders. Soft fill is reserved for transient status only: waiting, progress, done, error. Setup state is not transient.
Coloured icon chips on every row. Green, amber and purple rounded squares used as decoration.
Rule: chips are functional wayfinding and must map to a stable classifier output. Person orange and work cyan only, 2 per row, ≤5 categories app-wide. Row icons were none of that, so they are gone.
Purple as the accent. Primary buttons and highlights in #7f6df2.
Rule: the tint is #0a84ff. Purple is #bf5af2, means mind-change, and is typographic only. It never fills anything.
A decorative pipeline diagram. Three tinted bubbles with arrows, permanently in Settings.
Rule: accents are semantic, colour never decorates. The three legs now carry themselves as uppercase eyebrow headers, which is where a grouped list already puts its structure.
Em dashes throughout the app copy.
Rule: no em dashes anywhere in app copy. Periods and colons. Every string below is rewritten.

How Apple would do it, concretely

iOS Settings is the precedent and it is almost aggressively plain: a grouped inset list, a muted uppercase header above each group, an explanatory footer below it, and a right-aligned muted value on each row. There are no status cards. There is no progress diagram. Colour appears in exactly three places: the tint on interactive text, green on a live switch, red on a destructive row.

The pattern for an incomplete setup is Finish Setting Up Your iPhone, which is not a banner or a hero. It is one ordinary row, in an ordinary group, sitting first. Position is the emphasis. That is what the top group does here.

Where the colour went

Four hues on the whole surface, each stating one thing, none of them filling a card.

Tint #0a84ff
Back chevrons and the one primary button. Nothing else is blue.
Person orange #ff9f0a
Setup hints only: “Required”, “Not set up”, “Not chosen”. The token map already sanctions orange for setup hints, so no new meaning was invented.
Green #30d158
A live switch, which is the system control, not our colour.
Red #ff453a
One destructive row, on the screen that owns it.
What is doing the work instead. Position, since the first group is the one that needs you. Type scale, since a row title at 0.98/500 against a footer at 0.8/tertiary is already three levels of hierarchy. Whitespace, since 26px between groups separates them better than a border. And the right-aligned value, which is how a grouped list has always said “here is the state of this” without drawing a box around it.

Still true from before. Grouped into the product’s three legs from docs/architecture.md. Explanation lives in group footers, not row descriptions, which is what keeps rows at 58px on a phone. Every money, egress and vault write gate stays on the root screen; only the passive record of a consent moves.

Cost, unchanged. A group() builder beside the row grammar in src/settings/rows.ts, a restructure of renderMainScreen, two new destinations, one sheet, and a copy pass turning 18 row descriptions into 5 group footers.
