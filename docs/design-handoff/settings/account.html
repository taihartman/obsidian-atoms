Atoms Plus, all nine states

The most stateful screen in the plugin. AccountState is a sealed union of six kinds, and periodEnded carries three lapse variants, so nine screens render here. Two of them differ by a single row, for a reason worth keeping.

All commercial numbers below come from plus-pricing.json: $6 a month, $60 a year, 150 filings a period, $2 for 50 more, 14 day trial. Nothing here invents a price.

What changed on this screen

Three rows became one group
Today spends Status, Signed in as and Plan on three separate rows, where Status’s value is a whole phrase like “Monthly limit reached”. The state now names the group, and the rows carry facts.
One primary action, always
Each state has at most one thing to do, so it gets one button. Today Refresh status and Manage subscription compete with it as equal full-width buttons.
Refresh stops being a button
It is still there, and still load-bearing after a checkout returns. It is a quiet row, not a call to action, because a user should never have to press it to be correct.
One destructive row, not two
Today Sign out and Sign out all devices sit stacked in red. The nuclear one moves into the footer as a link, so the ordinary one reads as ordinary. It stays a real target and keeps its own confirm.
Paste session leaves
Advanced: paste session moves to Advanced, with the other escape hatches. It exists for one case: your email opens on a different device.
The promo path is locked, and inherited as-is
Decided 2026-08-13 (plus-promo-redeem), shipped in 0.7.10. Stripe owns the code string, so there is no field in the plugin. Use promo code opens monthly Subscribe checkout, never the trial. One email field serves all three ways in. The wording is “Use promo code”, matching Stripe: not “gift”, not “Have a code”. This redesign restyles that cluster and changes none of it.
A promo start must never offer a trial
An unfinished subscribeIncomplete resumes Finish Plus checkout. Offering Finish trial setup there would send a paying gift recipient down the card-for-trial path instead of applying their code. That is the whole reason setupKind is carried on the session.
Dates are dates
Today an ended period could render “Renews” against a date already in the past. Ended states say Ended, and only a live period says Renews.

Buying without a trial

The finding. The buy-now route already exists and is mislabelled. The service takes start_trial, subscribe_monthly and subscribe_yearly; the plugin's Use promo code button calls subscribe_monthly. A promo code is only something you may additionally type on Stripe's page. Separately, subscribe_yearly is unreachable from the plugin, though it is priced at $60 in plus-pricing.json.

The recommendation: do not add a Buy button. For a new email the trial strictly dominates subscribing. Both take a card, both cost $6 after, and the trial adds 14 free days. There is no reason for a new user to choose Subscribe, so offering both is offering a dominated option on the most crowded screen in the flow.

The person who genuinely cannot take a trial is someone who already used it, and today they tap Start free trial and get a 409. That is the real defect, and it is not a missing button. It is the screen asking a question the user cannot answer.

The principle. Keep a button for what the user knows about themselves. Remove the button for what only the server knows.

The signed-out cluster keeps its three locked buttons and its three locked labels: this is a behavioural change, not a visual one, and a far smaller piece of work than anything else in this folder.

Why the plan sheet sits here
It appears only once someone has decided to pay, which is exactly when comparing $6 and $60 is welcome rather than friction. On the signed-out screen the same choice would compete with the trial and slow down the path almost everyone should take. This is also the only change that makes subscribe_yearly reachable at all.
What stays locked
The 2026-08-13 cluster keeps Send sign-in link, Start free trial and Use promo code, with those exact words. Stripe still owns the code string and there is still no code field in the plugin. Nothing above is contradicted.
The judgment call worth challenging
Is Start free trial dishonest when it may reroute to checkout? I think the reroute is graceful enough, and the alternative label (Continue) throws away the strongest word on the screen for a new visitor. That is a funnel decision, not a design one.
Rejected: a Subscribe button beside the trial
It reads as offering choice while actually presenting a strictly worse deal to everyone eligible for the trial, and it puts a fourth button on the screen this whole redesign exists to calm down.
Copy rules applied. No em dashes. No invented pricing. “Complete Stripe checkout (card for the 14-day trial)” becomes plain language about what happens. The current Plan fallback string “Monthly or yearly — see Manage subscription” carries both an em dash and a cross-reference to a row that may not be rendered in that state; it is replaced by the period date, or by nothing.

Reachability. This screen sits at Settings → Who does the filing › → Atoms Plus ›. That is one tap deeper than today, where the account row is on the root screen. The trade is deliberate: the root screen now states which engine is active and how many filings are left, so the only reason to come here is to change something.
