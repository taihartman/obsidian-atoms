## Decisions & constraints

**Do not relitigate any of these.**

- **The release gate is a hard block** (user-directed). Merge to `master` may proceed with the gate
  open, but **no BRAT release is cut until a magic link has been opened from a mail client's in-app
  browser on a physical iOS device *and* a physical Android device**, both reaching signed-in. Both
  platforms, not one. It is human-only; you cannot satisfy it.
- **`verifier_hash` is base64url, not hex.** Shipped code is correct and pinned to the RFC 7636
  Appendix B vector at both ends. `hashVerifier` was deleted this session; `verifierMatches` imports
  `pkceChallengeS256` from `askHelpers.mjs`. **Borrow only that digest — never `verifyPkce`**, whose
  non-S256 branch is a plaintext compare this control must never accept.
- **Pending verifiers are tried newest-first, advancing only on `refused`** (decided this session,
  capped at the list length, ≤5). Peeking with only the newest would refuse a still-valid older link
  and make U7's five-slot list pointless (R16, U7 step 6). Affordable: the peek ceiling is 30/min per
  IP (`plus-service/src/ratelimit.mjs:74`).
- **The `vault=` param is attacker-controlled prose** and is never presented as the attested
  requesting vault. U9 doesn't read it at all.
- **Never log the magic token, the verifier, or a session token** (R11). `redact` covers all three
  shapes — the `mt_` rule is load-bearing, not belt-and-braces: a real magic token is 35 characters
  and passes straight under the generic 43-char rule.
- **Vault lanes.** All agent QA goes to `test_vault/` or `docs/media/demo-vault/`. Never mutate
  Remote Vault. Never copy plugin files into a personal vault. Do not cut a GitHub Release unless
  the user asks.
- `plus-service` **deploys to Fly before** any plugin build that depends on it (KTD11). The deploy
  carries one accepted regression: re-keying on `hashToken(token)` orphans magic-token rows minted
  before cutover, so in-flight links report expired for up to 15 minutes.
