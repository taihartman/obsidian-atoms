## Goal

Every retrieval number on this branch was measured against a corpus that **has never touched our
pipeline** — hand-declared links, titles generated by a string slice, no tags at all. Build a real
one: author a life story as daily notes, run it through the actual plugin pipeline, and get real
atoms with model-written titles, tags and reason-bearing link prose. Then re-measure. The owner was
explicit: *"the data must be like atoms."*

## Current status

Research is complete and committed; **no plugin code has been changed.** Everything lives in
`scripts/` and `docs/`.

**Settled and reproducible:**

- **Score shortlists on note BODIES, not titles.** Holds on every corpus tested. Title-only leaves
  39% of gold targets scoring literally zero; body+title leaves 23%.
- **Misses are absolute, not ranking failures.** A missed note scores *zero*, so widening k cannot
  recover it — only adding terms can. This is the load-bearing insight for everything below.
- **Graph expansion works, at the size originally predicted.** Hub-blocked 2-hop BFS from 25 BM25
  seeds reaches **29%** of the zero-score misses — about **+7 points** of honest recall@400 (76% →
  83%) for ~32 extra shortlist slots. Build it **only for daily filing**: in a graph-blind catch-up
  the only edges are atom→hub, so all reach is hub-mediated and hub-blocked reach is 0% by
  construction. ~58% of misses are in another graph component and unreachable at any depth.
- **Indexing the model's link prose is a free win** — 13 links won against 1 lost at k=400 with the
  link field weighted ×3 (p≈0.002). It converts 21 of 190 absolute misses into something k can
  reach.
- **Plus ships alphabetical-40 and it scores 0%** on the owner's real vault links. Robust.
- **Cost, caching, chunking** — all still valid, see the superseded handoff §Established.

**Corrected this session — do not re-inflate these:**

- The pre-run vault's filler notes had their **bodies set to their own titles**, so ~2/3 of every
  scoring pool were 3–4-token documents. BM25 normalises by the pool's average document length, so
  that collapsed the average and penalised the real atoms. Fixed in `scripts/lib/corpus.mjs` with a
  `--filler titleOnly|mismatched|coherent` switch; **`coherent` is the default and the realistic
  one.** Every harness now prints its pool's token-length distribution.
- That artefact inflated two published figures: two-hop reach was reported as 47% (**really 29%**)
  and link prose as "+16 won / 0 lost, strictly dominant" (**really +13 / −1**). Both docs are
  corrected.
- **Trust the zero-score column; treat every recall@k magnitude on the synthetic corpus as ±10
  points.** Measured: zero-score counts are byte-identical across all three filler shapes (whether
  a target shares a term with the query depends only on that pair), while r@40 for body+title
  swings 64% → 47% on padding alone.
- The "mean body is 1,943 chars" figure was averaging **non-atom** notes. Real atom captures average
  **123 chars** (median 97); only 5 of 37 exceed 200. The 200-char truncation debate is close to a
  non-question — decide it on memory, not recall.

**The owner's real vault (read-only, permission granted):** 373 notes, **37 atoms, 30 links**, only
**one** of which scores zero. Too small to settle anything — k=400 exceeds the whole vault. It did
show that **tags carry more indexable tokens than the captures themselves** (714 vs 650; +158% with
link prose), and all 37 atoms have them. That makes tags the largest untested lever, and it is
untestable until the new corpus exists.

## Why the corpus was stopped (2026-07-29)

The Next steps below were executed as far as step 4 and then **halted deliberately**. The brief,
the acceptance gate (`scripts/validate-corpus.mjs`) and the headless pilot harness
(`scripts/process-corpus.mjs`) are all committed and still work if this is ever restarted.

**What happened.** The brief was extended into a life-story brief, an acceptance gate was written
before commissioning anything, and authoring was delegated to `xai/grok-4.5`. The story bible came
back good. The first capture file passed **eight** gates and was rejected on sight: it had padded
captures to hit the mean length with stock closing phrases, manufactured the near-duplicate quota by
repeating adjacent captures verbatim, and maxed the short-capture gate at 107/107. The gate was
tightened (exact-duplicate reject, two padding metrics, a same-thread run cap, ceilings as well as
floors) and it now catches all of it — measured cleanly: 33% recurring trailing phrases vs 0% on an
honest corpus.

**Why that was not worth another round.** A validator only encodes flaws already seen. File E passed
eight gates and was still unusable; the next file passes nine and is wrong in a tenth way. This is
the third measurement artefact on this branch — after the title-only filler bodies that inflated
two published figures, and the 409-bullet claim corrected above.

**The deciding argument.** The findings that held up did so *because* they reproduced across corpora
with different flaws. What is still open — whether tags are the big lever, what recall@400 actually
is — is precisely what is most sensitive to whether the fiction resembles a real vault. A corpus
written to a brief we authored cannot settle that; it grades our own imagination. Meanwhile the
findings already in hand are enough to implement against, and one of them (alphabetical-40 scoring
0%) was measured on the **real** vault.

**Cost at the stop:** $5.19 of authoring tokens, over half of it on discarded output. **$0** of
Anthropic pipeline spend — the paid run never happened.

## Decisions & constraints

**Do not relitigate these.**

- **Ground truth must be declared by the author before any model runs.** If the model writes the
  links and you score retrieval against them, the shortlist is being graded against something that
  could only contain what it already surfaced. The answer comes out 100% and means nothing.
- **Atoms only. No public vaults, not even as padding.** The owner was explicit. Beyond genre, it is
  technically wrong: mixing long curated notes into the index moves the pool's average document
  length, which changes the BM25 score of every real atom. Padding is not inert.
- **Never handle the API key value.** Verify presence without printing (step 1). Never ask the owner
  to paste a key in chat — a key in a transcript is burned and must be rotated.
- **Vault lanes.** `analyze-vault-shortlist.mjs` is read-only and permitted against the owner's
  Remote Vault. Never write to it. All generated vaults go in `test_vault/` or `docs/media/demo-vault/`.
- **Quality over cost** — stated explicitly by the owner. The retrieval fix already created budget.
- **Plain English with this owner.** No growth or product jargon.
- **Multiplayer repo.** Research needs no claim; changing `context.ts` does — assigned Issue +
  `STATUS.md` row + draft PR first. See `docs/collab.md`.
- **Confirm before spending.** Give a figure and wait. The pilot exists so the full run is an
  informed decision.
