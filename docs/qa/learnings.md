Dated reports under `docs/qa/YYYY-MM-DD-*.md` are evidence. This file is memory. One row per trap. No credentials, tokens, or private account data.

| 2026-08-16 | Plus egress QA | **A `window.fetch` recorder covers 100% of Plus-gated egress, and that is worth knowing before you design the pass.** Every gated site binds `plusFetchRequest`, which is `window.fetch` (`plusClient.ts:27-69`) — so a monkey-patch can both *observe* and *block* real egress, making "no call happened" and "call went to the wrong host" distinguishable rather than inferred. It does **not** see BYOK classify or the paste-session `/v1/me`, which use `requestUrl`. | Install the recorder before any scenario: log `{url,method,hasAuth,bytes}` and reject non-loopback hosts with a TypeError, **recording the blocked attempt**. Zero-bytes on a `/v1/me` is the proof a probe was content-free. |
| 2026-08-16 | Plus session fixtures | **`plus-service` boots locally with no cloud credentials**, and `POST /v1/auth/start` returns a session token in the body — so a whole gate matrix can be driven without ever touching production or reading a magic link out of logs. The soft session it mints is accepted by `/v1/me` but **rejected by `/v1/classify` and the mirror routes**, so "the gate opened" is provable while "filing succeeded" is not. | `cd plus-service && npm start` (port 8787, in-memory). Mint with `/v1/auth/start` and a fake address. Say in the report which half the soft session can and cannot prove — do not round "request left with capture text" up to "filing worked". |
| 2026-08-16 | Plus gate verdicts | **A 401 only reaches the `refused` verdict when the body says "invalid session" or "expired".** `isSessionRejectedMessage` (`plusClient.ts:143`) is the gate, so a stub returning `{"error":"unauthorized","message":"nope"}` — or any proxy/WAF 401, or a 401 with no CORS headers — lands on `unreachable` with the offline copy instead. A QA pass that stubs a 401 to reach the refusal path will silently test the wrong branch and conclude the refusal surface does not work. | Shape the stub body like the real service (`{"error":"unauthorized","message":"invalid session"}`) when you want `refused`. Use a bare 401 deliberately when you want to exercise the proxy case. Assert which verdict you actually got, never infer it from the status code. |
| 2026-08-16 | Neuter checks | **A neuter that silently fails to apply produces a vacuous pass, and it looks exactly like a real one.** A `perl -0pi -e` substitution with `\x{2019}` in the pattern matched nothing; the test then "passed" against unmodified source and the guard looked load-bearing when nothing had been tested. | Assert the substitution **landed** before trusting the result — `grep -c` the neutered string and print the count, or neuter with an editor tool that errors on a missed match. A neuter check that cannot report "0 replacements" is not a check. |
| 2026-08-15 | Settings tab teardown | **Obsidian detaches `containerEl` *before* calling `hide()`** — probed at entry: no parent, no modal ancestor. Any cleanup that walks *up* from the container (`closest(".modal")`) silently no-ops on the way out, and the settings modal is **reused across visits**, so whatever you left on it stays for the session and applies to every other plugin's tab. A jsdom test cannot catch it: the harness keeps the container attached across `hide()`, so the bug passes. | Cache the outside element when you attach to it, and sweep the document on removal. In tests, `remove()` the container *before* calling `hide()` so the test reproduces the real order. Reading the state in the **same eval** as `app.setting.close()` also lies — `hide()` has not run on that tick; wait ~1.5s. |
| 2026-08-15 | Mobile rendering | **Desktop `emulateMobile` is not a mobile WebView, and "needs a real phone" is usually false.** A header defect sat recorded for a day as "probably an emulation artifact, someone check a phone" when two cheaper tests settled it: grep `styles.css` for any rule touching the surface, then disable the plugin's injected `<style>` in `eval` and look again — if it reproduces with our CSS off, it is not ours. For the half that genuinely needs mobile, the **Obsidian APK runs on an Android emulator**: `adb -s <emulator> install Obsidian-<v>.apk` (official GitHub release), push the plugin into a vault under `/sdcard/Documents/<vault>/.obsidian/plugins/atoms/`, and attach Chrome DevTools to the WebView for real computed styles. iOS Simulator cannot do this — App Store builds are device-only. | Settle ownership from the stylesheet before escalating to hardware. Drive the emulator when a real WebView is genuinely needed. **Pass `-s <emulator-id>` on every `adb` command** — a physical phone is often also attached, and a bare `adb` may target it. |
| 2026-08-15 | Driving Obsidian by mouse | **Do not fall back to computer-use clicks when an eval will not reach the screen. The screenshot's coordinates do not map to the live display.** Chasing a Notice frame for #509, every `left_click` inside the visible Settings window was refused with "would land on the desktop shell", at coordinates the returned image plainly showed as inside that window. The screenshot filter hides non-allowlisted apps at the compositor and they return the instant it is taken, so the image is a composite the real screen never showed. Roughly thirty tool calls went to this after the *documented* CLI route (the Settings eval and Notices rows below) was skipped. | Read the four rows below before driving anything: `settingTab.containerEl` for the screen, two evals for opening Settings, a `MutationObserver` for a Notice. They are the supported path and they work. If a Notice frame still cannot be reached from the CLI, hand the click to a human and say so in the report — do not spend a session on the mouse. |
| 2026-08-15 | Shared throwaway vault | **A peer session's `install-to-vault.sh` silently replaces your build mid-pass.** Verified: an install landed 0.8.0 at 09:19 and a probe confirmed it at 09:21; by 09:23 a peer worktree on another branch had overwritten `main.js` with its own 0.7.12. | 2026-08-15 | Any focus/keyboard-driven UI | **An unfocused Obsidian window fires no `focus`/`blur`/`focusin`/`focusout` events at all** — Chromium suppresses them when `document.hasFocus()` is false, which it is whenever the CLI drives while another app is frontmost. `document.activeElement` still moves, so a probe looks healthy while a blur-triggered feature silently never runs and reads as a product bug. `osascript activate`, `open -a Obsidian`, `remote.app.focus({steal:true})` and `win.focus()` all failed to take the foreground. | Attach CDP and emulate focus: `const wc = require("@electron/remote").getCurrentWebContents(); wc.debugger.attach("1.3"); wc.debugger.sendCommand("Emulation.setFocusEmulationEnabled", {enabled:true});`. ## How to add a row

- The next pass would otherwise re-pay the same cost (wrong handle, screenshot race, forbidden data path, construction that cannot fail).
- Not a one-off product bug with its own test — those go to the report and, if durable, `docs/solutions/`.
- Keep the row to one line. Link a solutions doc or nav-map row when the how-to is longer.
